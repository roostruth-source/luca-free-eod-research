# 루카 V0.3 — 날짜별 원본·기준 시각 묶음 감사 (2026-10-30)

## 이번에 막는 오류
한 날짜의 가격 자료를 복사하고 날짜만 여러 개 적어서 **여러 거래일을 검증한 것처럼** 보이게 만들면 안 됩니다. 새 `offline_multisession_audit.audit_session_bundle`은 날짜마다 서로 다른 `raw`(원본 가격 자료)와 `manifest`(기준 시각·종목 명단 봉인)를 **각각** 제출하도록 요구합니다.

- 각 항목에 `session_day_ny`, `raw`, `manifest`가 있어야 합니다.
- `session_day_ny`는 뉴욕 현지 날짜입니다. 이전의 `observation_date_utc`(UTC 날짜)와 다릅니다.
- 같은 뉴욕 날짜를 두 번 제출하거나 같은 관찰 ID를 재사용하면 오류를 냅니다.
- 기준 시각은 해당 뉴욕 날짜의 정규장 09:30~16:00(단축장 13:00) 안에 있어야 합니다.
- 모든 원본 1분봉도 **같은 뉴욕 날짜의 정규장 안에** 있어야 합니다. 시간대는 `America/New_York`로 변환하여 확인하므로 서머타임을 반영합니다.
- 2026년 예정 주말·휴장일은 거부합니다. 단축 거래일은 별도 표시합니다.
- 봉인 해시, 후보 종목 명단, 원본 안전 상태, 신호 계산 입력은 기존 검사기를 재사용해 확인합니다.
- 원본 내용의 해시를 계산하여 동일한 파일 내용을 다른 날짜에 반복 제출하면 오류를 냅니다.
- **시간만 바꾸고 가격 숫자는 똑같이 복사한 경우**도 별도 경고합니다. 실제로 같은 가격 흐름이 발생할 수도 있으므로 이 경우에는 차단 대신 사람이 확인할 수 있도록 표시합니다.
- 기준 시각과 1분봉 시각이 정각 분 단위(초 00)인지 확인하고, 원본 봉의 시간 순서가 뒤집히면 오류를 냅니다.
- 가격 봉이 **0개인 날짜**는 날짜 기록으로는 남기되, 실제 가격을 관찰한 날짜 수에는 포함하지 않고 경고합니다.
- 뉴욕 서머타임 전후에도 현지 09:30~16:00을 기준으로 검사합니다.
- 같은 종목이 여러 날 나타난 경우 종목-날짜 건수와 고유 종목 수를 따로 표시합니다. **합산 승률은 만들지 않습니다.** 날짜별 성적표만 남깁니다.

## 사용 예 (실제 시장 자료가 아닌 설명용 구조)
```python
from offline_multisession_audit import audit_session_bundle

report = audit_session_bundle([
    {"session_day_ny": "2026-10-29", "raw": raw_day1, "manifest": manifest_day1},
    {"session_day_ny": "2026-10-30", "raw": raw_day2, "manifest": manifest_day2},
])
```
각 `raw`는 기존 `LUCA_V03_IEX_RAW_OHLCV_EVIDENCE_V1` 형식이고, 각 `manifest`는 `create_commitment` 형식입니다. 위 코드는 **실행 예시**일 뿐 실제 원본 자료를 생성하거나 수집하지 않습니다.

## 검증과 아직 모르는 것
이 검사는 **입력 자료끼리 모순이 없는지** 확인할 뿐입니다. 누군가 가짜 가격 자료를 새로 만들어 해시까지 다시 계산하면, 이 기능만으로 실제 수집 여부를 입증할 수 없습니다. 해시(디지털 지문)는 파일 내용이 바뀌었는지 확인하는 도구이지, **그 파일이 언제 만들어졌는지** 또는 **실제 시장에서 왔는지** 증명하지 않습니다.

2026년 예정 NYSE 일정은 저장소의 고정된 달력만 사용합니다. 임시 휴장·실제 개장·특정 종목 거래정지는 확인하지 않습니다. 같은 종목을 여러 날 관찰하면 결과가 서로 영향을 받을 수 있으므로 **독립 표본 수는 검증 0으로 유지**합니다. 이 0은 실제 관찰이 없었다는 뜻이 아니라 검증 증거가 없다는 뜻입니다.

정규장 이외의 자료는 **이 새 감사 도구에서만** 거부합니다. 기존 프리마켓 연구 기능이나 데이터 수집 코드는 수정하지 않습니다.
